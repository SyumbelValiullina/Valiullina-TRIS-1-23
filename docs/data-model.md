# Модель данных

## Словарь терминов

| Термин курса | Термин моей темы |
|---|---|
| Ticket | заявка на услугу |
| Site | категория услуги |
| User | пользователь (заказчик / менеджер платформы / исполнитель) |

## Сущности

### ServiceRequest (заявка на услугу) — главный объект
- id (PK, число)
- number (человеческий номер, например ЗЯВ-0001)
- title (заголовок)
- description (описание)
- status (New / InProgress / Closed / Cancelled)
- categoryId (FK → ServiceCategory.id)
- createdByUserId (FK → User.id)
- assigneeUserId (FK → User.id, может быть пустым)

### ServiceCategory (категория услуги) — справочник
- id (PK, число)
- name (название категории: бухгалтерия, юрист, дизайн, логистика)

### User (пользователь)
- id (PK, число)
- name (имя или логин)
- role (заказчик / менеджер / исполнитель)

## Связи
- Одна категория услуги — много заявок.
- Один пользователь (заказчик) создаёт много заявок.
- Один пользователь (исполнитель) может быть назначен на много заявок.
- У новой заявки исполнителя может ещё не быть.

## Проверка 3НФ

Название категории услуги хранится один раз, в таблице ServiceCategory. Заявка содержит только внешний ключ categoryId. При переименовании категории меняется одна строка, поэтому текст названия не дублируется в каждой заявке.
